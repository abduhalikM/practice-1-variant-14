# Практическая работа №1 - вариант 14

Группа: ИКБО-71-24.

Реализованы первый и второй этапы: модель данных в памяти и удалённый вызов
её методов по TCP. Третий этап (MBT с Hypothesis) ещё не выполнен.

Записи хранятся в словарях на сервере и исчезают после его остановки.
В файл `journal.log` записываются ответы RPC, включая ошибки.
Журнал не используется для восстановления данных и не добавляется в Git.

## Подготовка

Нужен Python 3.10 или новее. Для работы программы достаточно стандартной
библиотеки Python. Все команды выполняются из корня проекта.

```powershell
git clone https://github.com/abduhalikM/practice-1-variant-14.git
cd practice-1-variant-14
```

Для проверки оформления кода можно установить отдельное окружение:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Активация окружения не требуется. На Linux вместо `py` используется `python3`.
Отдельная сборка проекта не нужна.

```text

    protocol.py    - кодирование и чтение сообщений
    server.py      - вызов методов модели и журнал ответов
    client.py      - класс RpcClient и интерактивный клиент
    rpc_demo.py    - демонстрация всех десяти удалённых методов
```

## Данные и связи

- `Participant`: `id`, `created`, `ip`, `locale`, `user_agent`.
- `Command`: `id`, `created`, `parameter`, `participant`, `description`,
  `tags`, `spawned`.
- `Reply`: `id`, `created`, `response`, `status`, `exception`, `command`,
  `cache_hit`, `duration`.

`id`, `created`, `participant`, `spawned`, `command`, `cache_hit`, `duration`
имеют тип `int`; остальные поля - `str`. Время `created` задаётся в секундах
Unix. Если его не передать, модель подставляет текущее время.

У участника может быть несколько команд. Поле `Command.participant`
содержит `Participant.id`. У команды может быть несколько ответов.
Поле `Reply.command` содержит `Command.id`.
Создание команды или ответа с несуществующей связью вызывает ошибку.
Идентификаторы назначаются автоматически отдельно для каждой сущности.

## Методы модели и клиента

Все методы ниже доступны у `DataModel` и `RpcClient` с одинаковыми именами
и параметрами. Методы создания принимают словарь `data` с полями записи
без `id`; `created` можно не указывать.

| Код | Метод | Результат |
|---:|---|---|
| 1 | `create_participant(data)` | Созданный участник |
| 2 | `get_participants()` | Список всех участников |
| 3 | `get_participant(record_id)` | Участник по идентификатору |
| 4 | `create_command(data)` | Созданная команда |
| 5 | `get_commands()` | Список всех команд |
| 6 | `get_command(record_id)` | Команда по идентификатору |
| 7 | `create_reply(data)` | Созданный ответ |
| 8 | `get_replies()` | Список всех ответов |
| 9 | `get_reply(record_id)` | Ответ по идентификатору |
| 10 | `get_recent_results(now=None)` | Соединённая выборка |

Выборка соединяет записи по `Participant.id = Command.participant`
и `Command.id = Reply.command`, отбирает `Command.created > now - 480`
и возвращает `description`, `ip`, `response`. Без Reply команда остаётся
с `response = None`. Несколько ответов дают несколько строк результата.
Команда, созданная ровно восемь минут назад, не попадает в результат.
Параметр `now` позволяет задать время для воспроизводимой проверки.

## Первый этап

Автоматическая демонстрация:

```powershell
py -m src.demo
```

Интерактивный режим:

```powershell
py -m src.repl
```

В открывшейся Python-консоли:

```python
data = {"ip": "127.0.0.1", "locale": "ru-RU", "user_agent": "Firefox"}
participant = model.create_participant(data)
model.get_participants()
model.get_participant(participant["id"])
model.get_participant(-1)
exit()
```

Последний запрос к модели показывает ожидаемую ошибку `KeyError`.

## Второй этап

Открыть два терминала в корне проекта.

В первом запустить сервер:

```powershell
py -m src.server
```

Также можно выполнить `run.bat` на Windows или `sh run.sh` на Linux.

Во втором выполнить демонстрацию:

```powershell
py -m src.rpc_demo
```

Демонстрация создаёт Participant, Command и Reply через TCP, вызывает
получение всех записей и получение по идентификатору для каждой сущности,
затем соединённую выборку. После успешных вызовов выводятся две ожидаемые
ошибки: отсутствие участника и неправильная связь при создании команды.

Для самостоятельных вызовов во втором терминале:

```powershell
py -m src.client
```

В консоли клиента можно выполнить:

```python
data = {"ip": "127.0.0.1", "locale": "ru-RU", "user_agent": "Firefox"}
p = client.create_participant(data)
client.get_participants()
client.get_participant(p["id"])
data = {"parameter": "x=1", "participant": p["id"]}
data.update({"description": "Проверка", "tags": "demo", "spawned": 0})
c = client.create_command(data)
client.get_commands()
client.get_command(c["id"])
client.get_recent_results()
data = {"response": "Готово", "status": "success", "exception": ""}
data.update({"command": c["id"], "cache_hit": 0, "duration": 15})
r = client.create_reply(data)
client.get_replies()
client.get_reply(r["id"])
client.get_recent_results()
client.get_participant(-1)
client.get_participants()
exit()
```

Первая выборка показывает команду без ответа, вторая - команду с ответом.
Запрос с `-1` вызывает `RpcError`; после него клиент продолжает работать.
Выход из клиента не удаляет записи на сервере. Сервер останавливается
нажатием `Ctrl+C` в первом терминале. После перезапуска модель пустая.

## Настройки

По умолчанию сервер слушает `127.0.0.1:9000`. Этот адрес предназначен
для запуска клиента и сервера на одном компьютере. Тайм-аут соединения
и ожидания сообщения - 5 секунд. Максимальное тело сообщения - 1 МиБ.
Значения находятся в `src/config.py` и `src/protocol.py`.

Адрес и порт можно задать аргументами запуска:

```powershell
py -m src.server --host 127.0.0.1 --port 9001
py -m src.rpc_demo --host 127.0.0.1 --port 9001
py -m src.client --host 127.0.0.1 --port 9001
```

Для двух компьютеров сервер запускается с `--host 0.0.0.0`, а клиент
с `--host IP_СЕРВЕРА`. Компьютеры должны иметь сетевое соединение,
а выбранный TCP-порт должен быть доступен через брандмауэр.

В коде `RpcClient(host, port)` создаёт клиент без немедленного подключения.
Каждый вызов метода открывает TCP-соединение, получает ответ и закрывает его.
Сервер также поддерживает несколько сообщений в одном соединении.
Все клиенты одного сервера работают с общей моделью в памяти.
Блокировка защищает модель от одновременного изменения потоками.

## Формат протокола

Запросы и ответы имеют одинаковый заголовок:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 5 байт | Длина только JSON-тела, big-endian |
| 5 | 1 байт | Код операции из таблицы методов |
| 6 | Переменный | JSON в UTF-8 |

Размер вычисляется в байтах UTF-8, а не в символах. В ответе повторяется
код запроса. TCP - поток байтов, поэтому `receive_exact()` читает данные
циклом до получения нужного размера. `encode_message()` формирует кадр,
`send_message()` отправляет его, `receive_message()` читает и проверяет.

Примеры JSON-тел:

```json
{"data": {"ip": "127.0.0.1", "locale": "ru-RU", "user_agent": "Firefox"}}
```

```json
{"record_id": 1}
```

Для метода без параметров передаётся `{}`. Для выборки используется
`{"now": null}` или заданное целое время.

Успешный ответ:

```json
{"ok": true, "result": []}
```

Ответ об ошибке:

```json
{"ok": false, "error": "KeyError", "message": "Запись не найдена"}
```

Сервер разрешает только десять перечисленных методов. Неизвестный код,
неверные аргументы и ошибочный JSON возвращаются как ошибки RPC.
Обрыв соединения не позволяет получить полный запрос и завершает обработку.
Клиент проверяет код и структуру ответа, ошибки модели передаёт как `RpcError`.

`journal.log` создаётся в текущей папке при первом ответе. Каждая строка
содержит JSON с временем UTC, кодом операции и полным ответом сервера.
Журнал дополняется при повторном запуске, а модель создаётся заново.
Для просмотра из PowerShell:

```powershell
Get-Content journal.log -Encoding utf8
```

## Проверки

Тесты сами запускают серверы на свободных портах. Отдельно запускать сервер
для тестов не требуется; рабочий `journal.log` они не изменяют.

```powershell
py -B -m unittest discover -s tests -v
.venv\Scripts\python.exe -m flake8 src tests --max-line-length=80
```

Ожидаемый итог тестов - `OK`. Flake8 при успешной проверке ничего не выводит.
Тесты проверяют модель, соединения и границу восьми минут, все 10 методов
через TCP, формат заголовка, UTF-8, дробление и склейку сообщений,
обрывы соединения, ошибки и журнал, параллельных клиентов и сброс модели.
